1. Cách sử dụng tài liệu và bộ bằng chứng
Giảng viên yêu cầu tài liệu hướng dẫn chi tiết xây dựng từng chức năng, kèm hình kiến trúc, sơ đồ hoạt động, hình diễn giải source code, hình giao diện, setup và danh sách prompt AI. Vì vậy mỗi chức năng quan trọng nên có cùng một bộ hồ sơ chuẩn.
Thành phầnPhải có gì1. Mô tảMục tiêu, actor, input/output, pre/post-condition.2. Activity/SequenceHình luồng từ UI → Controller → Service → Repository/External Service.3. Source evidenceẢnh đoạn code trọng tâm, khoanh/chú thích business rule, validation, security.4. UI evidenceẢnh form/list/detail/dashboard + trạng thái lỗi/thành công.5. Database evidenceBảng/entity liên quan, record trước/sau nếu cần.6. Test evidenceHappy path + edge/error/security case.7. AI evidencePrompt thật, phần AI hỗ trợ, phần nhóm sửa/kiểm chứng, link commit/PR.

10.1. Data model
Conversation(member_id, trainer_id) và Message(conversation_id, sender_id, content, sent_at, read_at). WebSocket chỉ vận chuyển realtime; DB là nguồn lịch sử.
10.2. Security
• Handshake/message phải gắn user đã xác thực.
• Service kiểm tra sender thuộc conversation trước save/publish.
• Không subscribe tùy ý conversation người khác.
• Giới hạn length; reject blank; escape/sanitize khi render để giảm XSS.
10.3. Notification
NotificationService nên ghi DB trước, sau đó publish realtime. Nếu client offline, lần đăng nhập sau vẫn đọc được notification chưa đọc.

15.3. Cách làm “hình diễn giải Source Code”
Chụp đoạn code ngắn 10–30 dòng, có line number. Bên cạnh đặt 3–5 callout: Input/Validation, Business Rule, Security/Ownership, Repository/External Service, Output. Không dùng ảnh dài 200 dòng không có chú thích.

16. Quy trình dùng AI an toàn và làm chủ code
BướcViệc phải làm1. Đưa contextNêu stack, package, entity, business rule, file liên quan; không gửi secret.2. Yêu cầu nhỏMỗi prompt một mục tiêu cụ thể; tránh “viết toàn bộ dự án”.3. Đòi giải thíchYêu cầu AI giải thích flow, edge cases, security, query.4. Tự reviewĐọc code, sửa naming, exception, transaction, ownership, validation.5. Chạy testBuild/run/test bằng dữ liệu thật; cố tình thử case sai.6. CommitCommit code đã hiểu; message theo feature.7. Prompt logGhi prompt, người dùng, mục tiêu, kết quả, chỉnh sửa, commit/PR.
Rubric AI 20% — Điểm cao không đến từ việc “AI viết nhiều”, mà từ việc nhóm sử dụng thường xuyên nhưng vẫn hiểu, sửa và làm chủ code AI sinh ra. Prompt log phải chứng minh quá trình đó.17. Danh sách prompt mẫu & Prompt Log
Các prompt dưới đây là mẫu/khung để nhóm sử dụng. Chỉ ghi là “đã sử dụng” trong báo cáo nếu nhóm thực sự dùng; Prompt Log cuối kỳ phải thay bằng prompt thực tế của nhóm.
Nhóm promptPrompt mẫuPhân tích yêu cầuTừ mô tả UTEFit sau, hãy tách actor Guest/Member/PT/Admin, use case, pre-condition, post-condition và business rule. Không thêm Manager vào MVP.ERDThiết kế ERD MySQL/JPA cho UTEFit với User, Trainer, Branch, MembershipPlan, Membership, Class, Schedule, Registration, TrainerRequest, PersonalTrainingSchedule, Payment, Checkin, Conversation, Message, Notification. Giải thích cardinality.Register DTOViết RegisterRequest DTO dùng Bean Validation cho Spring Boot; giải thích từng annotation; không xử lý business rule trong DTO.OTPThiết kế OtpService có expire, one-time use, resend invalidation và rate-limit đơn giản. Cho test cases trước rồi mới code.JWT SecurityĐề xuất Spring Security JWT cho Thymeleaf dùng HttpOnly cookie. Phân tích CSRF và route RBAC trước khi viết code.Class BookingViết pseudo-code Service đăng ký lớp với membership active, class open, capacity, duplicate, time overlap. Chỉ sau khi tao xác nhận mới viết Java.Time overlapViết truy vấn JPA/JPQL kiểm tra khoảng thời gian overlap và giải thích điều kiện start < existingEnd AND end > existingStart.PT ownershipReview endpoint PT accept request để đảm bảo PT A không xử lý request PT B. Liệt kê lỗ hổng trước khi sửa code.WebSocketThiết kế WebSocket STOMP chat Member–PT có authentication, conversation ownership, save DB và user-specific destination.CloudinaryViết interface CloudinaryService dùng chung cho avatar/branch/review, trả MediaUploadResult(url, publicId). Không đặt secret trong code.VNPayThiết kế flow Payment PENDING → VNPay → callback → verify signature → PAID → Membership ACTIVE. Nêu các dữ liệu không được tin từ frontend.Admin statisticsViết repository query aggregate revenue theo tháng và DTO cho Chart.js; tránh load toàn bộ Payment vào RAM.Review codeĐây là Service tao viết. Hãy review theo: 3 tầng, transaction, validation, authorization/ownership, race condition, exception, naming. Không rewrite nếu chưa giải thích lỗi.Test casesTừ business rule Class Booking này, sinh bảng test gồm happy path, boundary, invalid, unauthorized và concurrency risk.UITạo HTML Thymeleaf + Bootstrap 5 cho trang danh sách PT, giữ layout fragment hiện có, responsive và có search/filter/pagination.DiagramTừ sequence sau, viết PlantUML/Mermaid activity diagram. Không thay đổi tên actor/entity của UTEFit.DocumentationTừ commit/PR này, viết phần “mục tiêu – file thay đổi – logic – test – ảnh cần chụp” cho tài liệu hướng dẫn.DebugPhân tích stack trace này, chỉ ra root cause và 3 giả thuyết kiểm chứng theo thứ tự; không đoán mò và không đề xuất xóa security để chạy.
